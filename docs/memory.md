# Память и контекст диалога

## Три слоя

Приложение разделяет историю диалога, рабочую память задачи и долговременный профиль. История хранит сообщения. Рабочий слой содержит сведения о текущей задаче; долгосрочные предпочтения относятся к профилю. Сохранение предложенной памяти требует подтверждения пользователя в интерфейсе. Новая задача получает отдельный рабочий контекст; профиль сохраняется. Новый чат очищает переписку текущей задачи.

## Стратегии контекста

Режим `none` передаёт всю сохранённую историю. `sliding_window` передаёт последние N сообщений; по умолчанию `CONTEXT_KEEP_LAST=10`. `sticky_facts` дополнительно обновляет отдельные факты, используя вызовы модели. `branching` создаёт независимые ветки от checkpoint. Стратегия выбирается перед первым успешным сообщением; затем для её изменения нужен новый диалог.

## Память RAG-диалога

В режиме задания 25 есть отдельное состояние RAG-диалога с целью, уточнениями, ограничениями и терминами. Уточняющий вопрос разрешается с учётом этого состояния перед retrieval. Это отдельная возможность от /help.

## Изоляция /help

Команда /help отвечает по актуальному набору документации и MCP-источников. Она не переносит в запрос к модели рабочую/долговременную память, предыдущую переписку и скрытый previous_response_id. Поэтому посторонняя учебная задача не должна менять описание структуры проекта. Сами сообщения /help сохраняются в истории и восстанавливаются при перезагрузке страницы. Команда не обновляет цель или ограничения пользовательской задачи.
