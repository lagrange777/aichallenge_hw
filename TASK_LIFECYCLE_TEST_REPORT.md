## Обходы через API

- Прямой planning → done: HTTP 400, этап не изменён, отказ записан в журнал.
- Изменение этапа через save: HTTP 400, этап не изменён, отказ записан в журнал.
- Несуществующий этап unknown: HTTP 400, этап не изменён, отказ записан в журнал.
- Поле approvedPlanVersion внутри progress: HTTP 400, подтверждение не подделано.
- Повтор команды с прежней version: HTTP 409, актуальное состояние сохранено.

## Пауза и восстановление

На planning, execution и validation отдельно проверены:
- отключение отправки и переходов в браузере;
- отказ HTTP 409 на сообщение и сохранение состояния во время паузы;
- сохранение паузы после перезагрузки страницы;
- переключение на другую задачу и обратно с сохранением шага, плана, результата и версий;
- снятие паузы без перехода этапа и без автоматической генерации ответа.

Реальные прогоны дополнительно пересоздают хранилище и агента, затем отправляют «Продолжи».
Во всех шести продолжениях модель использовала сохранённые требования: дала план в planning,
реализацию в execution и замечания к сохранённому результату в validation.
