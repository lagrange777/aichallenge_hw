# Архитектура codex_chat_cli

## Назначение и структура каталогов

codex_chat_cli (модуль Go `codex-chat-cli`) — веб-приложение Codex Chat Web. Точка входа — `cmd/codex-chat/main.go`. HTTP-сервер, маршруты и встроенный интерфейс расположены в `internal/web/`; HTML, CSS и JavaScript — в `internal/web/static/`. Отдельной сборки frontend и npm не требуется.

`internal/agent/` управляет диалогом, стратегиями контекста, памятью, инструментами и проверкой ответов. Интерфейс `agent.LLM` отделяет агента от транспорта модели. `internal/openai/` реализует этот интерфейс через OpenAI Responses API. Ключ `OPENAI_API_KEY` остаётся на сервере, в браузер не передаётся. Генерация в этом проекте использует облачную модель OpenAI; это не сервис локальной Qwen из соседнего репозитория.

`internal/config/` читает настройки окружения. `internal/history/` хранит переписку. `internal/memory/` хранит рабочую и долговременную память. `internal/profile/` отвечает за профили пользователей. `internal/models/` содержит модели, ограничения контекста и расчёт стоимости.

## Документы и RAG

`internal/docindex/` разбивает документы на чанки, получает эмбеддинги и сохраняет SQLite-индекс. CLI индексации — `cmd/doc-index/`. Старый учебный корпус хранится в `documents/corpus/`; путь его индекса задаёт `DOCUMENT_INDEX_PATH`. `internal/rag/` выполняет поиск, query rewrite и фильтрацию для обычного RAG-чата.

`internal/agent/grounding.go` проверяет ссылки и диапазоны строк, восстанавливает точные цитаты и отдельно проверяет поддержку утверждений моделью. Если подтверждений недостаточно, ответ содержит «не знаю» и просьбу уточнить вопрос. Семантическая проверка моделью снижает риск ошибок, но не является математической гарантией истинности.

## MCP и планировщик

`internal/mcpclient/` подключается к MCP-серверам через Streamable HTTP, получает инструменты и проверяет разрешения. Настройки подключений хранятся в файле `MCP_PATH`. В `internal/scheduler/` реализованы задания планировщика; локальный MCP endpoint планировщика — `/mcp/scheduler`. `internal/brokerdemo/` содержит учебные сервисы заявок, валидации и брокера; это симуляция, а не реальная биржа.

## Ассистент разработчика /help

`internal/projecthelp/` создаёт отдельный локальный BM25-индекс README, `docs/**/*.md` и выбранных корневых инструкций. Команда `/help вопрос` всегда использует этот индекс, независимо от переключателя обычного RAG. Старый учебный корпус не участвует в /help. `internal/agent/project_help.go` обрабатывает команду и сохраняет ответы в истории текущего диалога.

`cmd/project-mcp/` запускает отдельный MCP-сервер; его реализация находится в `internal/projectmcp/`. Инструмент `git_branch` получает текущую ветку, HEAD-коммит и признак detached HEAD, а `project_files` возвращает ограниченный список отслеживаемых публичных путей. Данные получают реальными вызовами MCP для каждого вопроса, а не зашивают при сборке. Произвольных команд, записи файлов и diff в этих инструментах нет.

Для /help доступны только документация и результаты чтения MCP. Команда не запускает инструменты брокера/планировщика, не извлекает историю других задач и не меняет их память. Сами сообщения /help сохраняются в истории. Каждый новый /help собирает свежие доказательства; сохранённый старый ответ не считается текущим состоянием Git.
