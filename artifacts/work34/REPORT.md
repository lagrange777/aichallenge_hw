# День 34: проверка файлового ассистента

## Результат

Два сценария и два повтора прошли через реальный HTTP-интерфейс Docker-приложения, настоящий MCP SDK и OpenAI Responses API (`gpt-5.3-codex`). Это самостоятельный выбор моделью инструментов и файлов, не заранее зашитая последовательность операций.

| Сценарий | Запуск | Прочитано файлов | Запросов к модели | Секунд | Результат |
|---|---|---:|---:|---:|---|
| 1 | Первый запуск | 3 | 5 | 12.90 | applied |
| 1 | Повтор | 3 | 3 | 6.35 | no_changes |
| 2 | Первый запуск | 8 | 6 | 23.32 | applied |
| 2 | Повтор | 5 | 4 | 6.84 | no_changes |

Сценарий 1: в изолированной копии документации намеренно изменены GET /api/history на POST /api/history и /healthz на /health. Ассистент восстановил реальные метод и путь по исходникам. Сценарий 2: создан ADR о подключении MCP со ссылками на сервер, клиент и конфигурацию. Повторы завершились без новых предложений и без изменений файлов.

Для первых запусков проверено: минимум три разных прочитанных файла, самостоятельный list/search, готовый diff, отсутствие записи до применения, совпадение файлов после применения с содержимым предложения. Для повторов проверено: нет патчей и SHA-256 файлов рабочей копии не меняются. Это проверки поведения и воспроизводимости; они не являются автоматическим доказательством полной смысловой корректности любого сгенерированного документа.

Исходные ответы, журнал MCP, содержимое прочитанных файлов, diff, токены и все проверки: [evaluation.json](evaluation.json). Патчи сохранены отдельно рядом. Скрипт проверки: `scripts/evaluate-work.py --seed-doc-mismatch` (новые платные запросы). Скрипт отказывается перезаписывать существующий отчёт; для повторного прогона задайте новый `--output`.

## Исправления, найденные при проверке

В первом UI-прогоне модель обнаружила расхождение, но ограничилась предложением подготовить патч позже. Старое правило ошибочно интерпретировало отсутствие патча как «изменений не требуется». Добавлен MCP-инструмент finish_task, обязательный явный исход задачи и ограниченные напоминания. Если модель продолжает отвечать обещанием вместо выполнения, задача получает ошибку, а не успешный статус. Регрессия проверяется TestAnOfferIsNotSuccessfulCompletion. Исходный проблемный ответ сохранён в [initial-ui-issue.json](initial-ui-issue.json).

В первоначальном ADR модель чрезмерно обобщила политику DestructiveHint для demo-инструментов и указала статус «Принято». Инструкция уточнена: описывать точные условия из исходников и оформлять новый ADR как предложенный. Исходный прогон сохранён в initial-evaluation.json; окончательная версия повторно проверена отдельно в evaluation.json. Документы модели всё равно требуют просмотра перед применением.

Между записанными сегментами сокращены паузы; ответы и журнал не подменялись. Полное декодирование видео прошло без ошибок. Метаданные: [video.json](video.json).

Задачи из видео и отдельная проверка совпадения сохранённых файлов: [video-tasks.json](video-tasks.json). В видео первый сценарий прочитал 4 файла, второй — 6, повтор — 4. Подробности инструмента и исходные результаты доступны в веб-журнале. Cookie/идентификаторы владельцев не включены в публикуемые данные.

## Технические проверки и границы

- Полный `go test ./...`, `go vet ./...`, `go test -race ./internal/filework`.
- Все тесты также выполнены при сборке Docker. Внешний Project MCP healthy, HTTP `/healthz` отвечает. После force-recreate контейнера задачи восстановились в том же браузере, применённые файлы сохранились.
- Реальный MCP initialize / tools/list / tools/call через in-memory транспорты; отдельный сетевой endpoint для файлов не публикуется.
- Публичная копия содержит 166 файлов. Исходный checkout не меняется при применении; запись разрешена только в README.md и docs/*.md.
- Проверены изоляция владельцев задач, запрет .env/служебных путей и симлинков, отсутствие модельного инструмента применения, конфликты зависимостей, сохранение и восстановление задач, повторное применение.
- Локальный режим не заменяет многопользовательскую авторизацию; применение нескольких файлов не является транзакцией, устойчивой к отключению питания между rename. Полный preflight и откат обычных ошибок записи предусмотрены.

Логи тестов: [tests.txt](tests.txt). Запуск и ограничения описаны в [docs/file-assistant.md](../../docs/file-assistant.md).
