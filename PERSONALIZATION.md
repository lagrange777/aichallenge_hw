# Персонализация ассистента

Профиль задаёт язык, уровень подготовки, стиль, подробность, формат, описание
пользователя и дополнительные ограничения. Пользователь создаёт и редактирует
его на вкладке «Профили». Примеры «Новичок», «Разработчик» и «Руководитель»
заполняют форму; профиль сохраняется только после нажатия кнопки сохранения.
Кнопка «Использовать» переключает активный профиль.

## Связь с памятью

- Реестр профилей браузера хранится в `PROFILE_PATH/<browser-id>.json`.
  Запись атомарная, файлы имеют права `0600`.
- У каждого профиля свой идентификатор владельца памяти и истории. Это даёт
  отдельные задачи, рабочую и долговременную память, переписку и предложения.
- Настройки профиля доступны всем его задачам. При возвращении к профилю
  восстанавливается его последняя активная задача.
- Старые данные автоматически относятся к профилю «Основной»: его идентификатор
  совпадает с прежним владельцем данных, поэтому перенос файлов не нужен.
- Профиль сохраняется после перезапуска и очищения диалога. Извлечение памяти
  не меняет настройки профиля автоматически.

## Подключение к запросам

В начале `Agent.Ask` загружается актуальный профиль. Один снимок используется
во всём ходе: в основном запросе, предварительном подсчёте токенов и служебных
запросах извлечения фактов, предложений и сжатия истории. Транспорт добавляет
профиль в инструкции в виде JSON и правил применения. Для языка, краткости
и формата дополнительно формируются конкретные инструкции из выбранных полей.

Приоритет пользовательских предпочтений:

1. Явная просьба в текущем сообщении и параметры текущего ответа.
2. Настроенный профиль.
3. Прежние предпочтения из памяти и переписки.

Системные и служебные правила сохраняют приоритет. Внутренние запросы получают
профиль как контекст, но сохраняют требуемый JSON или формат summary. Они не
должны оформлять служебный результат в стиле пользовательского ответа.
Значение «По запросу» оставляет соответствующую настройку текущему запросу и памяти.

Язык сообщения сам по себе не переопределяет язык профиля. Например, русский
вопрос при английском профиле должен получить английский ответ. Явная просьба
«ответь по-русски» переопределяет настройку для этого ответа.

Под каждым новым ответом сохраняется раскрываемый снимок профиля. Он показывает
переданные настройки, а не обещание, что модель безошибочно выполнила каждое
предпочтение. Редактирование профиля не изменяет снимки предыдущих ответов.

## Проверка реальной модели

20 сентября 2026 года выполнены четыре независимых запроса к настроенной модели
`gpt-5.3-codex`. Первые три получили один вопрос: «Как организовать кеширование
запросов к API?». История диалога отсутствовала, настройки были переданы только
в профиле. Полные ответы и расход токенов сохранены в
[PERSONALIZATION_EVAL.json](PERSONALIZATION_EVAL.json).

| Профиль / сценарий | Наблюдаемый результат | Объём, слов¹ |
|---|---|---:|
| Новичок: русский, подробно, шаги | Объяснение кеша и терминов, последовательные шаги, пример | 642 |
| Разработчик: английский, кратко, Go | Английский ответ и один пример на Go | 211 |
| Руководитель: русский, кратко, список, без кода | Список вариантов, рисков и действий без кода | 154 |
| Разработчик + просьба ответить по-русски одним абзацем без кода | Русский ответ одним абзацем, без кода | 75 |

¹ Разбиение по пробельным символам, включая код. Все четыре ответа без эмодзи.
Указание «кратко» — предпочтение: целевые 80–180 слов не являются жёстким
ограничением. В примере разработчика ответ занял 211 слов вместе с кодом.
Эти четыре примера демонстрируют поведение, но не гарантируют его для всех запросов.

Для повторения (четыре платных запроса к настроенному API):

```sh
go run ./cmd/profile-eval -output profile-evaluation.json
```

Команда читает те же переменные окружения, что сервер, и не меняет пользовательские
профили, память и переписку. Она сохраняет ответы, но не выдаёт автоматическую
оценку качества. Сравните язык, структуру, подробность и ограничения по таблице.

## Автоматические проверки

```sh
go test -race ./...
go vet ./...
```

Проверяются валидация и сохранение профилей, изоляция браузеров, миграция старого
диалога, переключение и восстановление после перезапуска, снимки настроек,
отклонение устаревшего запроса чата и ошибки сохранения. Тест транспорта проверяет
передачу профиля в основной и служебный запросы, подсчёт токенов, приоритет
параметров ответа и сохранение служебных инструкций. Эти тесты не подменяют
проверку соблюдения настроек реальной моделью.
